# clipbench

Speech-to-text models are sold on clean benchmarks: audiobooks, meetings, read speech. Real short-form
video is different. Music runs under the voice, people talk fast, use slang, switch languages mid
sentence, and talk over each other. clipbench measures how well current models handle that: which
model wins on which kind of clip, what breaks each one, and what it costs per hour of audio. Every
number comes from code you can rerun, on clips anyone can rebuild from their YouTube ids, scored
against captions a person checked against the audio.

## Quickstart

```bash
make setup                                   # uv sync with local Whisper and AWS extras
make build-data sample fetch-audio           # read Vako captions, sample 150 clips, fetch audio
uv run clipbench review                      # check and correct references at http://127.0.0.1:8765
uv run clipbench run --providers all --tier verified --dry-run   # what it would cost
make run report                              # run, score, analyse errors, write report and site
```

Paid providers need keys in `.env` (see `.env.example`). A provider without a key is skipped with a
message. The budget cap is `budget_usd` in `clipbench.toml`; a run that would cross it does not start.

## What you get

- `results/<run_id>/report.md` and `site/index.html`: headline table with 95% confidence intervals,
  accuracy against cost, accuracy by clip type, hallucination, error examples, drafted findings, limitations.
- `web/`: the public web app (landing page, leaderboard, compare, model picker, account features),
  fed by `clipbench export`. See [docs/WEB.md](docs/WEB.md).
- `results/<run_id>/*.parquet`: per-clip scores, aggregates, paired comparisons, stability.

How the numbers are made: [METHODOLOGY.md](METHODOLOGY.md). Every judgement call: [DECISIONS.md](DECISIONS.md).

## Commands

| command | does |
|---|---|
| `clipbench data fetch-info` | fetch missing info.json metadata with yt-dlp, gently |
| `clipbench data build` | scan caption tracks, classify them from info.json, write `data/manifest.parquet` |
| `clipbench data sample --n 150 --seed 7` | stratified sample, at most 10% per channel |
| `clipbench data fetch-audio` | audio only, one at a time, 10 s apart, 16 kHz mono WAV plus original |
| `clipbench review` | local review UI to build the verified set |
| `clipbench run --providers all --tier verified [--dry-run]` | transcribe with every system, cached and budget guarded |
| `clipbench score <run_id>` | normalise, align, bootstrap, paired tests, slices |
| `clipbench errors <run_id>` | substitution pairs, worst clips, clips every model fails (flagged for re-review) |
| `clipbench report <run_id>` | report.md, charts and the static site |
| `clipbench export <run_id>` | JSON for the web app |
| `clipbench publish --check` | fails if anything publishable holds audio or reference text |

`<run_id>` can be `latest`.

## Systems tested

Whisper large-v3 and turbo (local, mlx-whisper), Groq Whisper, Deepgram, AssemblyAI, ElevenLabs Scribe,
Gemini Flash, Amazon Transcribe, YouTube automatic captions, and Wayin where its output exists. Models
and prices as checked: [docs/providers.md](docs/providers.md).

## Add a provider

1. Check the provider's current docs: model, endpoint, language parameter, word timestamps, batch price
   per minute, minimum billing, data use and opt-out flags.
2. Add a section to `clipbench/providers/pricing.toml` with `model_id`, `usd_per_minute`,
   `min_billed_seconds`, `checked_url`, `checked_on`, `data_policy`, `opt_out`.
3. Write `clipbench/providers/<name>.py`: subclass `HttpProvider` (or `Provider` for SDKs and local
   models), set `id` and `env_keys`, implement `transcribe()`, and set every opt-out flag the API offers.
   Anything that changes the output goes in `self.options`, which is part of the cache key.
4. Register it in `clipbench/providers/registry.py` and add its key to `.env.example`.
5. Test it with `httpx.MockTransport`: the request, the parsed result, a 429 then success, and no key.

## Reproduce from video ids

The clip list is published with every run (`results/runs/<run_id>/rows.parquet`, column `video_id`).
Audio and captions are not, because they belong to the creators. To rebuild:

```bash
uv run clipbench data fetch-info          # metadata for each id
uv run clipbench data build && uv run clipbench data sample --n 150 --seed 7
uv run clipbench data fetch-audio
```

Videos that were deleted or made private since will be missing; the report says how many clips each
run scored.

## Data and ethics

Audio, caption text and references live in `data/`, which is gitignored (a test checks it). Only code,
video ids, scores, aggregates, charts and error snippets of a few words are published. Audio is fetched
slowly, one file at a time. Providers that would train on API data are only used with their opt-out set.
