# v2 contract

clipbench v2 is "the independent benchmark for captions on real short-form video". This file is the
shared contract every module codes against; it extends docs/INTERFACES.md and docs/WEB.md.

Positioning line: "Which speech-to-text should your video app use? The independent benchmark for
captions on real short-form video: accuracy, word timing, hallucination over music, and cost, in five languages."

Repo URL: https://github.com/Abhishek-B-R/clipbench (never abhishekbr).

## Languages

`en` (first), `ja`, `ko`, `es`, `hi` (Hindi and Hinglish, mixed Devanagari and Latin). A language is
**published** only when it has >= 100 verified clips AND >= 6 providers with ok rows in its latest run
(local Whisper, YouTube auto, and four paid APIs). Below that the site shows the method, the dataset
spec and progress counts ("first results: N of 100 clips verified"), never a ranking.

## Dataset spec (`datasets/<lang>/clips.csv`, committed, public)

Columns: `platform` (youtube | tiktok | instagram), `video_id`, `start_ms`, `end_ms` (both blank for the
whole video), `channel_id`, `category`, `license_note`, `source` (which importer added it).

`clip_id`: `<video_id>` for a whole video, `<video_id>@<start_ms>-<end_ms>` for a window. clip_id is what
the existing code calls `video_id` in Clip, Reference, rows, scores and verified files (least invasive);
the raw platform id lives in `source_id`.

Categories (exact strings): `talking_head`, `vlog_music`, `gaming`, `comedy_skit`, `cooking_tutorial`,
`news_explainer`, `other`.

Diversity rules (enforced in code, `clipbench data check`): per language >= 30 channels, no channel above
5% of the set, >= 6 of the categories present (not counting `other`).

Importers: `clipbench data import-vako --lang L` (Vako's caption store, one importer among others),
`clipbench data import-ids <csv> --lang L` (any list of public ids), `clipbench data discover --lang L
--channels datasets/<lang>/channels.csv` (find Shorts with creator captions from a channel list).
`datasets/<lang>/channels.csv`: `platform, channel_id, handle, category, note`.

Vako is credited in one README line only and appears nowhere in the UI.

## Reference additions (verified file and `Reference`)

```json
{"category": "vlog_music",
 "nonspeech_spans": [{"start_ms": 0, "end_ms": 2400, "kind": "music"}],
 "codeswitch_spans": [{"start": 12, "end": 20, "lang": "en"}],
 "punctuated": true}
```

- `nonspeech_spans`: tagged in the review UI on the audio timeline; kinds `music`, `sfx`, `silence`.
- `codeswitch_spans`: character offsets into the corrected text, tagged by selecting text in the review UI.
- `punctuated`: the reviewer confirms the verified text has deliberate punctuation and casing (only those
  clips count for caption readiness).
- Word timings: `data/align/<clip_id>.json` = `{"aligner": "<name>@<version>", "words": [{text, start_ms, end_ms}]}`
  from `clipbench align` (forced alignment of the verified text), or the creator track's timings when it has them.
  `Reference.words` and `Reference.timing_source` ("creator" | "aligner:<name>" | null) carry them.

## Audio condition

`music` if the clip has a `background_music` tag or any `nonspeech_spans` of kind music, else `no_music`.

## New score columns (`scores.parquet`, per provider x clip, repeat 0)

`timing_n_words, timing_median_ms, timing_p90_ms, timing_within_200ms` (share 0..1; null when the provider or
reference has no word timings), `nonspeech_minutes, halluc_nonspeech_words, halluc_per_nonspeech_min`,
`punct_f1, casing_acc` (null unless `punctuated`), `codeswitch_ref_len, codeswitch_errors,
codeswitch_error_rate` (null without spans), `category, audio_condition`.

Aggregates gain the same metrics (corpus style where it makes sense, medians for timing) and slices
`slice_kind` = `category` and `audio_condition`.

## Export (`web/public/data/runs/<run_id>.json`) additions

`languages: [{lang, verified_clips, providers_ok, published, channels, categories}]` per run and in
index.json, `clips[].kind` ("short" | "window"), `clips[].start_s`, `clips[].category`,
`clips[].audio_condition`, the new metric aggregates, and `providers[]` policy fields
(`retention_days, trains_by_default, opt_out, policy_url`). Every number the site shows comes from these
files or the database. Copy never types a count or a percentage.

## Web flags

`VITE_ACCOUNTS` (default off): hides sign-in, account, requests, alerts and the nav entries; the Worker
code stays. With it off the site is fully static apart from `/api/v1`.
