# v3 contract

Extends docs/V2.md and docs/INTERFACES.md with the data shapes for the v3 features: streaming, semantic WER,
drift, condition slices, sweeps, formatting, multiple valid references, long-form, compute, diarization,
language ID, entities, style, reliability, caption export and the provider feature matrix.

## Standing rules

- No paid call without the owner's approval; dry runs only. Anything that costs money per run (LLM judge,
  canaries, streaming, sweeps) goes through `clipbench.budget` (estimate, BudgetGuard) and the result cache,
  and prefers Cloudflare Workers AI where a model exists there.
- No audio or caption text in anything public. Every number on the site is computed from data.
- No em or en dashes anywhere. Plain commit messages, one commit per feature.
- Nothing is fabricated: data that needs a person (human labels, verified references, speaker turns) is
  collected through tooling; until it exists the feature reports "not enough data" and is not published.

## Verified file additions (`data/verified/<clip_id>.json`, `Reference`)

```json
{"conditions": ["music", "sfx", "multiple_speakers", "fast_speech", "whisper_shout", "outdoor_noise", "code_switching"],
 "speaker_turns": [{"start_ms": 0, "end_ms": 4200, "speaker": "A"}],
 "entity_spans": [{"start": 10, "end": 18, "type": "brand"}],
 "alternatives": [{"start": 3, "end": 5, "options": ["今日", "きょう"]}],
 "itn_spans": [{"start": 20, "end": 24, "kind": "number"}]}
```

- `conditions`: audio conditions (A4). `music` is also implied by the `background_music` tag or a music
  non-speech span; the rest are set in the review UI. Constant `CONDITIONS` in clipbench/models.py.
- `speaker_turns`: who speaks when (B15). Speakers are labels local to the clip.
- `entity_spans`: character offsets of proper nouns and brands; `type` in person, brand, place, product, other (B17).
- `alternatives`: per-span valid alternatives to the reference text (A7). Offsets into the reference text;
  the reference text itself is always one of the options.
- `itn_spans`: spans whose written form matters for formatting (A6); `kind` in number, date, time,
  currency, percent, unit.
- All offsets are code point offsets into the corrected `text`, re-anchored by the review UI like codeswitch_spans.

## Provider capabilities (`pricing.toml`, `[<id>.features]`)

`languages, batch, streaming, word_timestamps, diarization, language_id, custom_vocabulary,
max_file_minutes, retention, training_opt_out`, each value plus `<key>_url` and `<key>_checked_on`.
This table is the source for the feature matrix (B20) and for which runs are possible.

## Run options and Result additions

`clipbench run ... --diarize --detect-language --keyterms datasets/<lang>/keyterms.txt`: passed to each
provider as options (part of the cache key); providers that do not support an option skip it and record
that in `Result.raw_response["clipbench_unsupported"]`.

`Result` gains: `speakers` (per word speaker label, parallel to words, or null), `detected_language`
(or null), `retries` (int), `http_status` (last status, or null). Rows gain `retries`, `timed_out` (bool),
`http_status`, `detected_language`, `options` (json).

## Output artifacts per run (`results/<run_id>/`)

Each feature writes its own files; the export integrates them. Numbers only, no text.

| file | feature |
|---|---|
| `stream_rows.parquet`, `stream_aggregates.parquet` | A1 streaming (own run kind: `results/runs/<run_id>` with `run_meta.kind = "stream"`) |
| `semantic.parquet`, `semantic_aggregates.parquet` | A2 semantic WER (plus `judge_calibration.json`) |
| `canary/` history lives in `results/history/<lang>.parquet` | A3 drift |
| `sweeps.parquet` | A5 SNR sweeps (`results/sweeps/<sweep_id>/`) |
| `formatting.parquet` | A6 punctuation error rate, casing, ITN accuracy |
| `lattice` columns in scores.parquet: `error_rate_lattice` | A7 (score.py owner adds them) |
| `longform.parquet` | A8 long-form |
| `compute.parquet` | A9 RTFx, memory, model size |
| `diarization.parquet` | B15 |
| `lid.parquet` | B16 |
| `entities.parquet` | B17 |
| `style.parquet` | B18 fillers and profanity, as style properties |
| `reliability.parquet` (also across runs in `results/history/reliability.parquet`) | B19 |
| `captions.parquet` | B21 SRT/VTT caption-level timing and readability |

Columns: always `provider, model_id, video_id (clip_id), tier, language` plus the feature's metrics; each
feature also writes an aggregate file with `provider, tier, language, slice_kind, slice, n_clips` and
its metrics with 95% bootstrap CIs where it is a rate.

## Export additions (`web/public/data/runs/<run_id>.json`, `index.json`)

Keys: `streaming`, `semantic`, `drift` (events: provider, date, metric, before, after, ci), `history`
(per provider series), `sweeps`, `formatting`, `longform`, `compute`, `diarization`, `lid`, `entities`,
`style`, `reliability`, `captions`, `features` (the capability matrix). Each is null when the run has no
such data. Slices gain `slice_kind = "condition"`.

`run_meta.latency_mode` (2026-10-21): `{sequential_providers: bool or null, max_concurrency: int or null,
contended: bool, text: string}`. `contended` is true for runs that ran providers at the same time and for runs
recorded before the field existed (`sequential_providers` null); show `text` next to any latency number.
Aggregate `latency_p50`, `latency_p95` and `rtf` cover only requests made in the run (no cache hits, no
zero-latency track reads), so they are null for youtube-auto.


## Publication gate fields

Emitted by `clipbench export` (code: `clipbench/report/rules.py`, `clipbench/report/export.py`) so the site
and the Worker read the gate instead of recomputing it. Every number below is computed by Python; the web
side only displays it and must not re-derive eligibility, ranking order or verdicts.

### Language status

Each entry of `runs/<run_id>.json` `languages[]` and of `index.json` `languages[]`:

| field | type | meaning |
|---|---|---|
| `lang`, `verified_clips`, `published` | as before | `published` is true only when all three `gate` flags are true |
| `providers_ok` | int | now the number of ELIGIBLE providers (= `providers_eligible.length`); kept under its v2 name so old readers gate on the right number |
| `channels`, `categories`, `largest_channel_share` | as before | legacy descriptive fields over the scored clips (categories may include manifest guesses); not used by the gate |
| `providers_eligible` | string[] | provider ids with coverage >= `min_coverage`, sorted by id |
| `providers_excluded` | object[] | one per other provider seen in the run: `{provider, coverage, n_scored, n_skipped, n_error, reason}`; `coverage` is a share 0..1 rounded to 4 places, or null when the run has no verified clips; `n_skipped`/`n_error` are null when the run has no rows.parquet; `reason` is a display sentence |
| `min_coverage` | float | the threshold used (clipbench.toml `min_provider_coverage`, default 0.9) |
| `verified_diversity` | object | `{channels: int, largest_channel_share: float or null, categories: string[], passes: bool, problems: string[]}` over the verified evaluation clips; `categories` are the distinct categories from verified files, `other` left out; `problems` are display sentences, empty when `passes` |
| `gate` | object | `{verified_clips_ok, providers_ok, diversity_ok}`, all bool: `verified_clips >= 100`, `providers_ok >= 6`, `verified_diversity.passes` |

Old exports lack the new fields: treat a missing `gate` as not published.

### Aggregates

Every row of `aggregates[]` gains:

- `eligible` (bool): the provider is in `providers_eligible`. Rows of excluded providers stay in the table
  so the site can explain the exclusion; they must never be ranked or compared.
- `coverage` (float 0..1 or null): the provider's coverage on the verified evaluation clips (the same
  value on every tier, metric and slice row of that provider).
- `ci_low_cluster`, `ci_high_cluster` (float or null): channel-clustered 95% interval (sensitivity
  analysis); `n_channels` (int or null): channels behind it.
- `mean_clip_error_rate` (float or null): mean of per clip error rates, a secondary number next to the
  corpus `error_rate`.

### Ranking

`ranking` (new top-level key of `runs/<run_id>.json`): `{<tier>: {<metric>: [{provider, rank, error_rate,
ci_low, ci_high, n_clips}]}}` for slice `all`, eligible providers only, ordered by `error_rate` ascending
with ties broken by provider id; `rank` is 1-based and unique. It is `{}` when the language is not
published. The site's leaderboard must use this order and these providers.

### Paired

`paired[]` now holds only tests between two eligible providers, already Benjamini-Hochberg adjusted:
`verdict` is the adjusted verdict (use it for any "beats" or "ahead of" wording), `verdict_raw` the
unadjusted one, `p_adjusted` the BH value. Each row gains `ci_low_cluster`, `ci_high_cluster`,
`p_value_cluster` and `n_channels` (null when the run has no channel information); the clustered values
never change `verdict`.

### Findings

Each item of `findings/<lang>.json` `findings[]` gains `cluster_sensitive` (bool): true for a comparison
whose channel-clustered interval crosses zero; its `text` then ends with a sentence saying so and
`numbers` carries `ci_low_cluster`, `ci_high_cluster`, `p_value_cluster`. False for every other finding
and when no channel information exists. Findings never mention an excluded provider.

### What the web and Worker need to change (not done in this pass)

- Gate on `gate` / `published`, show `providers_ok` as "eligible providers", list `providers_excluded`
  with their `reason`, and show `verified_diversity.problems` while unpublished.
- Build the leaderboard from `ranking`, not by sorting `aggregates`; hide or grey rows with
  `eligible: false`.
- Read verdicts from `paired[].verdict` (adjusted) and badge `cluster_sensitive` findings.
- `web/src/lib/types.ts` `LanguageStatus` and the Worker's /api/v1 schemas gain the fields above.
